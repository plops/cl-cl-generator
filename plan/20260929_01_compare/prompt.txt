Dabei handelt es sich um in **Common Lisp** geschriebene Transpiler, die von einer Common Lisp-ähnlichen Input-Sprache in verschiedene Zielsprachen übersetzen. 

**Das Ziel (Architektur-Design):**
Konzipiere eine Architektur, wie man die Input-Sprache und die in Common Lisp geschriebenen Generatoren so refactoren und anpassen kann, dass ein *neuer, vereinheitlichter Transpiler* aus demselben Input flexibel verschiedene Output-Sprachen erzeugen kann (nicht beschränkt auf die bisherigen vier Sprachen). Denkbar wäre z.B. die Einführung einer generischen Zwischenrepräsentation (AST/IR). Du hast auch entscheidungsgewalt ueber die zugelassenen Outputsprachen: wenn eine Sprache (z.B. Verilog) zu sehr aus der Reihe faellt, kann sie auch weggelassen werden.

**Schritt 3: Erstellung des Implementierungsplans (`task.md`)**
Schreibe eine Datei `task.md`. Dieser Plan muss so detailliert sein, dass ein *völlig unabhängiger AI-Agent* danach die komplette Programmierung in Common Lisp übernehmen kann. 
Die `task.md` muss enthalten:
- **Kontext-Aufbau:** Eine Liste von Dateien, die sich der Folge-Agent zwingend anschauen muss, mit jeweils einem Satz Begründung.
- **Lisp-spezifische Code-Hygiene (Klammern!):** Weise den Agenten *ausdrücklich und eindringlich* darauf hin, dass KIs bei Common Lisp extrem anfällig für Klammer-Fehler (Parenthesis-Mismatch) sind. Der Agent muss gezwungen werden:
  1. Den Code pedantisch und korrekt einzurücken (Indentation), um die Struktur zu wahren.
  2. Änderungen nur in winzigen, nachvollziehbaren Schritten durchzuführen.
  3. Nach *jeder* kleinen Code-Änderung sofort die Lisp-Syntax zu prüfen (z.B. durch Laden der Datei in `sbcl` oder `ecl`), bevor er weiterarbeitet.
- **Git-Vorgaben:** Eine strikte Anweisung an den Agenten, dass alle Commits im "Conventional Commit"-Format und mit einer umfassenden Beschreibung (Body) erfolgen müssen.
- **Serielle Task-Liste:** Unterteile die Implementierung in chronologische Schritte. Jeder Schritt muss Validierung und Testing beinhalten. 
- **Phasen:** Gliedere die Tasks logisch, z.B. in: 1. Core-Implementierung (generische Zwischenrepräsentation/AST), 2. Refactoring der sprachspezifischen Backends, 3. Unit-Tests, 4. Integration-Tests (Validierung der generierten C++/Python/Rust-Codes).
